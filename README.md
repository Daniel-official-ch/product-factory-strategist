# Стратег Фабрики продуктов

ИИ-агент для руководителя цифрового продукта. Он ведёт от размытого запроса («почему падает удержание?») до продуктовой и коммуникационной стратегии с планом проверки и не бросает после решения. Это папка с инструкциями, знаниями и скриптами: открываете её в Claude Code или Cursor и работаете в чате.

Что агент делает за вас:

- ставит задачу и спрашивает только то, что важно для следующего шага;
- собирает материалы (файлы, таблицы, открытые сайты) и помнит, откуда каждое сведение;
- отделяет факты от гипотез и прогнозов, честно называет пробелы;
- предлагает не меньше трёх вариантов, включая «оставить как есть» и «закрыть направление», у каждого сильные возражения;
- пишет согласованные продуктовую и коммуникационную стратегии, план проверки с условиями остановки;
- после решения следит за основаниями и пересматривает выводы, когда приходят новые данные.

Ключи и файл `.env` не нужны. Платных сервисов нет, кроме вашей подписки на Claude Code или Cursor.

## Первый запуск (3 минуты)

Нужно: Python 3.11 или новее и Claude Code либо Cursor. Чистая установка и тесты проверены на Python 3.12.16 и 3.13.1; Python 3.11 на машине проверки отсутствовал и отдельно не тестировался.

1. Скачайте репозиторий и откройте папку в терминале.
2. Создайте отдельное окружение и установите зависимости (обычно около 20–60 секунд, зависит от сети):

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
   python3 -m pip install -r requirements.txt
   ```

3. Проверьте, что инструменты работают (должна появиться строка «проект не найден» — так и должно быть, проекта ещё нет):

   ```bash
   python3 tools/cli.py status
   ```

4. Откройте папку в Claude Code (`claude` в терминале) или в Cursor (File, Open Folder).
5. Наберите в чате:

   ```
   /start Почему у нашего сервиса падает удержание?
   ```

   Вместо примера напишите свой запрос, можно размытый. Если запрос не указан, агент спросит его сам. В Cursor slash-команда может не сработать: тогда напишите `@cmd_start` и приложите запрос (или «начни новый проект по правилу cmd_start»).

Что вы увидите: агент поздоровается, коротко объяснит, как идёт работа, создаст проект в `workspace/current_project/` и задаст до трёх вопросов с пояснением, зачем он их задаёт. В начале каждого ответа будет строка:

```
Этап 1 из 6: Постановка задачи | сделано: ... | ждёт тебя: ... | потрачено: ...
```

Если вместо работы агент отвечает ошибкой про `yaml` или другой модуль, вы пропустили шаг 2.

## Как идёт работа: 6 этапов и 3 вопроса к вам

| Этап | Что происходит | Что результат |
| :--- | :--- | :--- |
| 1. Постановка задачи | Вопрос, цель, получатель, ограничения, данные | `deliverables/01_problem_brief.md` |
| 2. Сбор материалов | Загрузка файлов, таблиц, открытых сайтов | `raw_materials/` |
| 3. Исследование и пробелы | Вопросы исследования, утверждения с цитатами, что неизвестно | `deliverables/02_research_and_gaps.md` |
| 4. Варианты и возражения | Не меньше 3 вариантов, красная команда | `deliverables/03_options_and_objections.md` |
| 5. Стратегия и план проверки | Продуктовая, коммуникационная, план проверки | `deliverables/04_product_and_comm_strategy.md` |
| 6. Сопровождение решения | Журнал решения, пересмотр при новых данных (`/update`) | `deliverables/05_decision_log.md` |

Агент остановится и спросит вас в трёх местах: подтвердить бриф (этап 1), выбрать вариант (этап 4), принять стратегию (этап 5). Без вашего ответа он дальше не идёт, и скрипт это проверяет: `validate-step` для этапов 1, 4 и 5 не пройдёт, пока ваше решение не записано. Всё остальное делает сам.

Команды:

| Команда | Когда |
| :--- | :--- |
| `/start` | Начать новый проект |
| `/resume` | Продолжить с сохранённого места |
| `/options` | Построить варианты и возражения |
| `/strategy` | Написать стратегию и план проверки |
| `/update` | Учесть новые данные после решения: что устарело и что пересматривать |

## Остановиться и продолжить

Напишите «стоп» в любой момент. Агент сохранит точку продолжения (`workspace/current_project/HANDOFF_CONTEXT.md`) и скажет, как вернуться.

Чтобы продолжить, откройте новый чат в той же папке и наберите:

```
/resume
```

Агент прочитает сохранённое состояние, а не вспомнит разговор: покажет этап, что сделано, что ждёт вашего решения и сколько потрачено. То же без чата:

```bash
python3 tools/cli.py resume
```

## Исправить результат

Вы вправе исправить что угодно.

- **Текст документов** (`workspace/current_project/deliverables/*.md`): отредактируйте файл и скажите агенту «я поправил файл». Он перечитает его и не откатит правки.
- **Данные проекта** (`state.json`, `evidence_db.json`, `options.json`, `sources.json`, `calculations.json`, `decisions.json`): агент замечает ручную правку по контрольной сумме и останавливается с кодом 3. Это защита, а не поломка. Примите правку командой:

  ```bash
  python3 tools/cli.py accept-edit --reason "Поправил описание варианта OPT-01"
  ```

  Пока правка не принята, `status` показывает `integrity: manual_edit_detected` и предупреждение, а остальные команды отвечают кодом 3.

  Команда проверит, что данные остались корректными. Если нет, она перечислит нарушения; исправьте их и повторите.
- **Уточнить задачу или поменять решение**: просто скажите об этом в чате. Агент внесёт изменение и пересмотрит всё, что от него зависит.

## Сколько это стоит

Статус и `/resume` показывают токены и сумму по этапам.

- **Claude Code:** расход пишет хук `Stop` из `.claude/settings.json` по журналу сессии (`ide_exact`). Он учитывает проект из переменной `STRATEGIST_PROJECT`, иначе активный проект (его запоминают `init` и команды с явным `--project`), иначе `current_project`. Для одного проекта `current_project` ничего делать не нужно; если вы ведёте несколько проектов, работайте с `--project <имя>` и проверяйте расход в `status`. Цены лежат в `config/pricing.yaml`.
- **Cursor:** хуков нет, агент записывает оценку в конце этапа (`ide_estimated`). Это оценка, а не точная цифра; точные цифры в личном кабинете Cursor.

Экономия: чтение источников делает дешёвый субагент `reader` (haiku), критику вариантов и стратегии — сильный `red-team` (opus), модельных респондентов — `synth-resp` (sonnet). Расчёты, проверку цитат и контрольные суммы делают скрипты без модели.

## Как агенту можно верить

- Каждый факт имеет источник и дословную цитату. Скрипт проверяет, что цитата есть в тексте источника: `python3 tools/cli.py verify-quotes`.
- Свои выводы агент не может записать как факт: они остаются гипотезой.
- Перед приёмкой стратегии и при `/resume` агент запускает `python3 tools/cli.py verify-run`: проверяет цитаты, что каждая строка с `[FACT]` ссылается на подтверждённое утверждение, что нет ссылок на отозванное и что расход учтён. Команда только читает; вы можете запустить её сами в любой момент и увидеть долю подтверждённых фактов.
- Факты из синтетических демо-таблиц (первая строка файла `# SYNTHETIC`, например в `demo/antispam/`) разрешены, но в документах помечены `[DEMO-DATA]` и считаются отдельно: `verify-run` показывает `demo_data_share` рядом с `verified_share`. Это данные для демонстрации, в реальном проекте их заменяют данными продукта. Без метки проверка не пройдёт.
- Тексты из загруженных источников — данные. Команды из них агент не выполняет.
- Ответы модельных респондентов помечены как синтетические и не доказывают спрос.

## Таблицы и новые данные

Три команды, которые агент вызывает сам. Вручную они нужны, только если вы хотите увидеть то же, что видит он.

- **`analyze-table --source SRC-02`** проверяет загруженную таблицу до того, как из неё берутся факты: пропуски, смесь единиц (`12%` и `0,12`), проценты вне 0–100, текст в числовом столбце, дыры и повторы в месяцах, выбросы. Ничего не меняет в проекте, отчёт кладёт в `analysis/` (путь в ответе, поле `report_path`). У xlsx с несколькими листами нужно указать лист: `--sheet <имя>`. Найденное «error» агент либо записывает как пробел, либо объясняет в `02_research_and_gaps.md`. Строка `# SYNTHETIC` данными не считается.
- **`ingest-update`** подключает новые данные вместо старых. Нужно сказать, что заменяется (`--replaces SRC-01`) или какие утверждения устарели (`--claims CLM-003`), и зачем (`--reason`). С `--dry-run` команда только показывает результат. Подтверждённые утверждения остаются, остальные становятся «заменёнными» и ведут себя как отозванные. Расчёты, которые надо пересчитать, перечислены в `recalc_needed`: пересчёт записывается под новым номером `CALC`. Источник, который уже заменён, повторно под другим номером не заменить: заменяйте актуальный. Если подтверждённое утверждение было на демо-данных, оно демонстрационным и остаётся; чтобы стало реальным, его регистрируют заново по новому источнику.
- **`impact --id CLM-003`** только читает и отвечает на вопрос «что рухнет, если это изменится»: какие утверждения, варианты и решения от него зависят и в каких строках документов оно упомянуто. Принимает `SRC`, `CALC`, `CLM`, `OPT` или `DEC`.

Решение при этом агент сам не меняет: он покажет затронутое и спросит вас. Если решение затронуто, оформляется новое, старая запись остаётся в журнале.

## PDF для руководителя

Документы проекта лежат в Markdown. Чтобы получить читаемую версию, которую можно переслать:

```bash
python3 tools/cli.py export-pdf
```

PDF каждого документа из `workspace/current_project/deliverables/` появится в `deliverables/pdf/`. Метки `[FACT]`, `[HYPOTHESIS]`, `[FORECAST]`, `[DEMO-DATA]` и сноски в PDF остаются как есть. Команда только читает: данные проекта и контрольная сумма не меняются, `verify-run` после неё даёт тот же результат. Один произвольный файл: `export-pdf --md <файл.md> --out <файл.pdf>`. Если команда ответила про `reportlab`, выполните `pip install -r requirements.txt`. Если не нашлась картинка из документа, в PDF будет рамка «Скриншот ... будет добавлен» и предупреждение в ответе.

## Что умеет и чего нет

Готово: ядро из 6 этапов, загрузка `.md`, `.txt`, `.csv`, `.xlsx`, `.pdf`, `.docx` и открытых сайтов, необязательный MCP-сервер, реестр утверждений, варианты с возражениями, стратегия с проверкой структуры, остановка и продолжение, учёт расхода, интервью (`skills/skill_interview.md`).

Пока нет, не рассчитывайте на это:

- проверка живого диалога в Cursor (см. «Ограничения Cursor»). Готовые прогоны демонстрационных кейсов лежат в `demo/antispam/run` и `demo/family_safety/run`, проверить их можно командой `python3 tools/cli.py --workspace demo/antispam/run verify-run` (подробности в README прогона);
- распознавание сканов: PDF без текстового слоя не загрузится, распознайте текст и сохраните как `.txt`;
- персональные данные в таблицах: проверка таблицы (`analyze-table`) смотрит единицы, пропуски и периоды, но не ФИО (раздел «Таблицы и новые данные»).

## Ограничения

- **Персональные данные.** При загрузке (`ingest-source`, `ingest-url`, `add-user-input`) скрипт ищет телефоны и адреса почты. Нашёл — загрузка остановится и покажет маскированные примеры; повторите с `--redact-pii`, и значения заменятся на `[телефон скрыт]` и `[почта скрыта]` (копия бинарного файла при этом не сохраняется). Закрытые данные компаний не загружайте.
- **Имена людей.** Скрипт ищет их эвристикой: ФИО с отчеством, инициалы («И. И. Иванов»), подписи под отзывами. Нашёл — загрузка **не** остановится, а в ответе появится `name_warnings` со строками. Агент покажет их вам, а вы решаете, что из этого настоящие имена. Скрыть: повторите загрузку с `--redact-terms "Имя1;;Имя2"` (слова заменятся на `[имя скрыто]`, сами имена нигде не сохраняются). Если источник уже загружен: `python3 tools/cli.py redact-source --id SRC-03 --terms "Имя1;;Имя2" --reason "обезличил отзывы"`. Команда откажет, если имя входит в цитату факта по этому источнику; тогда сначала решите, что делать с фактом. Тишина без предупреждений не гарантия: имя без отчества и вне подписи под отзывом скрипт пропустит.
- **Сайты, закрытые от скриптов.** Если страница отвечает 403 или отдаёт заглушку («проверяем браузер»), сохраните её в браузере как HTML и загрузите `ingest-url --url <адрес> --id SRC-XX --from-file <файл>`. Флаг `--force` нужен, только если вы убедились, что страница настоящая.
- **Что детектор ПДн не видит:** адреса проживания; имена, не похожие на ФИО с отчеством, инициалы или подпись под отзывом (одинокое «Анна» в середине абзаца); телефон, разорванный версткой (например переносом строки посреди номера); колонтитулы в `.docx` и метаданные PDF (автор и т. п.); персональные данные в таблицах (`analyze-table` их не смотрит). Проверьте такие файлы глазами до загрузки.
- **Защита от ручной правки обнаруживает, а не запрещает.** Агент технически может отредактировать файл мимо скриптов; при следующей команде контрольная сумма это покажет.
- **Запись решения не удостоверяет личность человека.** `record-decision` может вызвать и сама модель; `validate-step` проверяет наличие и вид записи, а не того, кто её создал. Поэтому решение должно подтверждаться вашим явным ответом, а не только файлом. Надёжное техническое разделение требует внешнего подтверждения на уровне IDE или ОС и пока не реализовано.
- **Выводы агента проверяйте.** Цитаты проверяются скриптом, но выбор цитат и выводы остаются за моделью. Поэтому вам предлагают подтвердить бриф, вариант и стратегию.
- **Синтетика.** Модельные респонденты помогают найти гипотезы, но не заменяют интервью с людьми.

## Ограничения Cursor

Проект рассчитан на Claude Code и проверялся в нём. В Cursor работают те же правила и скрипты, но есть отличия. Живой прогон в Cursor ещё не проведён, поэтому пункты ниже — известные расхождения по устройству, а не результат теста.

- Slash-команды `/start`, `/resume` и другие в Cursor лежат как правила `.cursor/rules/cmd_*.mdc`, а не как встроенные команды. Если `/start` не сработал, напишите в чате «@cmd_start» (или «начни новый проект по правилу cmd_start») и приложите запрос.
- Нет автоматического учёта токенов: хука `Stop` нет, агент записывает оценку (`ide_estimated`). Сверяйте с дашбордом Cursor.
- Субагенты `reader`, `red-team`, `synth-resp` задаются в `.claude/agents/`. Подхватит ли их ваша версия Cursor, зависит от версии. Если нет, агент выполняет эти роли сам в основном чате: без экономии на дешёвых моделях.
- Правила для Cursor лежат в `.cursor/rules/` и `AGENTS.md`. Они собираются из `prompts_src/` командой `python3 tools/cli.py build-rules`. Править их вручную не нужно, правка потеряется.
- Состояние проекта (`workspace/`) полностью переносится: начните в Claude Code, продолжите `/resume` в Cursor. Потеряется только то, что хранится вне папки: история чата и привязка расхода к сессии.

## MCP-сервер (необязательно)

Нужен, если вы хотите вызывать инструменты проекта из MCP-клиента, а не через терминал. Без него всё работает как раньше, `/start` и остальные команды от MCP не зависят.

1. Установите зависимость: `pip install "fastmcp>=4.1"` (в `requirements.txt` она только закомментирована).
2. Скопируйте блок из `config/mcp.example.json` в настройки MCP вашего клиента (Claude Code: `.mcp.json`; Cursor: `.cursor/mcp.json`) и замените относительные `tools/mcp_server.py` и `workspace` на абсолютные пути, если клиент запускает сервер не из папки репозитория. Активный конфиг в репозиторий не кладётся.
3. Сервер запускается командой `python3 tools/mcp_server.py` (stdio, без баннера). Проверен запуск через stdio-клиент; живое подключение к Claude Code и Cursor не проверялось, при расхождении ориентируйтесь на документацию вашего клиента. Папку данных можно задать переменной `STRATEGIST_WORKSPACE`.

Что доступно: каждая команда `cli.py` как инструмент, имя с подчёркиванием (`register_claim`, `validate_step`, `status`), у каждого есть необязательный параметр `project`. Результат: `{"ok": true, ...}` или `{"ok": false, "exit_code": 1|3, "error": ..., "hint": ...}`; ошибка проверки приходит как результат, не как сбой сервера. Инструменты вызывают тот же `cli.py`, поэтому блокировка, контрольные суммы и проверки те же.

Чего нет намеренно: `accept-edit` (принять ручную правку может только человек, выполните её сами в терминале), `redact-source` (обезличивание источника тоже выполняется только через CLI), а также служебных `build-rules` и `parse-transcript`. Если сервер ответил про `fastmcp`, выполните шаг 1.

| `knowledge_base/` | Методики (`frameworks/`) и шаблоны документов (`templates/`) |
| `tools/` | Скрипты: `cli.py` и модули. Вся проверка и учёт здесь |
| `workspace/` | Данные проектов. Состояние задачи хранится отдельно от правил и методик |
| `tests/` | Автотесты: `python3 -m pytest -q` |
| `docs/diagrams/` | Схемы рабочего процесса и архитектуры |
| `docs/report/` | Описание работы для жюри и его PDF-версия |
| `benchmarks/` | Сравнение с обычным чатом, исходные ответы и проверки |
| `config/` | `pricing.yaml`, `mcp.example.json` и необязательный `.env.example` |

Правила для Claude Code и Cursor (`CLAUDE.md`, `AGENTS.md`, `.claude/agents|commands`, `.cursor/rules`) собираются из `prompts_src/`. Изменили источник — запустите `python3 tools/cli.py build-rules`, проверка актуальности: `python3 tools/cli.py build-rules --check`.

Список всех команд скриптов: `python3 tools/cli.py --help`.
